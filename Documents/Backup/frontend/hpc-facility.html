HPC Facility

The high-performance computing facility of the Department of Physics supports computational physics, large-scale simulations, data-intensive research, and interdisciplinary scientific computing carried out by students, researchers, and faculty.

About the Facility

HPC Cluster at Physics department is a heterogeneous, hybrid HPC based on Intel Xeon processors designed and implemented for HPC Technology. It comprises 1 master node, 6 login nodes in each HPC.

User Guidelines

Usage Policy and Guidelines

We are trying to better organize the facility and to this end a survey is being conducted to gather two basic details from the users. It is mandatory for the users to take the survey.

A job scheduler is installed on the cluster to manage load and allocate resources. Users can submit jobs only via job scheduler for better optimization of resources. Any job submitted directly on the compute nodes would be killed without any notice, this applies to all the users.

There are several users on this cluster. Therefore, the best policy would be to submit short jobs and resubmit them as often as you want. This is possible if you create checkpoints/restarts in simulations, so that you can restart from the previous state of your simulations. This is just to ensure that the waiting time, before the job starts running, for you and other users is minimal. Kindly avoid running jobs for a long time.

Regularly take backup of your data and do not allow it to accumulate on the server storage for long time.

Tutorials

Accessing the cluster

To access the HPC you need to "ssh" the login server.

The master node is primary gateway to the rest of the cluster, which has a job scheduler. You may submit jobs to the queue and they will run when the required resources are available.

Please do not run programs directly on login node. Login node is used to submit jobs, transfer data and to compile source code.

By default, user data save in /home directory. These directories are available on master node as well as the other nodes on the cluster.

Remote access from Windows Computer

Using any open source "ssh" client applications for Windows you can login and access the cluster. Enter the user name along with IP address or Hostname with which you wish to connect.

e.g. Username@10.33.1.18 / username @ 10.33.1.54

Enter your password when prompted, and press Enter.

Remote access from Linux Computer

Linux systems provide a built-in SSH client, so there is no need to install any additional package. Open the terminal, connect to an SSH server by typing the following command:

ssh Username@hostname

Scheduler

PBS/Maui Shark uses Slurm 20.03.3 open-source as the workload manager for the HPC facility. The queues have been defined to meet different computational requirements.

Storage Policy

Important: Users must submit jobs from the /scratch/USER directory.

Users can check their /home and /scratch quota using the myquota command.

Users are advised to maintain local backups of their data. Storage and charging policies are subject to change.

General Procedure - Batch Script & Job Submission

HPC Cluster provides a well-defined software environment to compile and run applications using Environment Modules. These tools ensure that the correct versions of compilers, libraries, and applications are available during a user session and within SLURM batch jobs.

Using Environment Modules

module avail # list all available modules module load intel/version # load the Intel compiler module unload intel/version # remove Intel compiler from environment module show intel/version # display module environment changes

Sample Slurm Job Script

#!/bin/bash #SBATCH -J lammps-mpi # job name #SBATCH -o %j.out-myjob # stdout output file #SBATCH -e %j.err-myjob # stderr error file #SBATCH -p shared # partition: shared, medium, large, gpu #SBATCH -N 2 # total MPI tasks #SBATCH -n 2 # threads per task #SBATCH --ntasks=80 # utilize 80 cores #SBATCH --mem=23000 # min memory per node in MB #SBATCH --mem-per-cpu=6000 # min memory per allocated CPU #SBATCH --mail-user=user@phy.iitkgp.ac.in # email for job status #SBATCH --mail-type=ALL # send mail for all event types if [ -n "$SLURM_CPUS_PER_TASK" ]; then omp_threads=$SLURM_CPUS_PER_TASK else omp_threads=1 fi module load apps/lammps/12Aug16/intel mpirun executable export OMP_NUM_THREADS=$omp_threads mpirun -bootstrap slurm -n $SLURM_NTASKS exe

Submit the Job

Once the required modules or Spark packages are loaded, prepare a SLURM batch script and submit with sbatch.

$ sbatch slurm-job.sh Submitted batch job 108 $ squeue JOBID PARTITION NAME USER ST TIME NODES NODELIST(REASON) 108 standard simple user R 0:01 1 compute-0-2

For more information refer to the SLURM Documentation.
